1. ТӨСЛИЙН ТАНИЛЦУУЛГА / PROJECT OVERVIEW
================================================================================

Зорилго:
Монголын хүнсний дэлгүүрт зориулсан POS (Point of Sale) desktop аппликейшн.
Хэрэглэгч double-click хийхэд хоёр native цонх нээгдэнэ: кассын цонх + 
үйлчлүүлэгчийн дэлгэц. Зориулалт: хүсний дэлгүүрийн кассчин/админ нэгдсэн
passwordless интерфейс.

Үндсэн онцлогууд:
- Баркод сканнер (USB scanner = keyboard input)
- Бэлэн, карт, холимог төлбөр
- Үйлчлүүлэгчийн дэлгэц (хоёр дахь дэлгэц)
- ESC/POS дулааны принтер
- eBarimt (Монголын Татварын Газрын цахим баримт)
- Автомат нөөц хуулбар (30 хоног)
- Offline-first ажиллагаа

Хэрэглэгчийн тоо: 1 кассчин/admin өөрчлөгдөөгүй
Хэл: Монгол (зөвхөн)

4. МЭДЭЭЛЛИЙН САН / DATABASE (SQLite)
================================================================================

Schema (6 tables):

products:
  id, barcode (UNIQUE), name, price (INTEGER, MNT), category, stock_qty,
  unit, low_stock_threshold, is_active (1/0), created_at

cashiers:
  id, name, pin_hash, role (cashier/manager), is_active, created_at

sales:
  id, cashier_id (nullable), payment_type (cash/card/split/return),
  subtotal, total, cash_given, change_given, card_amount, cash_amount,
  ebarimt_id, ebarimt_qr, ebarimt_status (pending/sent/failed/skipped),
  created_at, return_of_sale_id (nullable, FK to sales.id)

sale_items:
  id, sale_id (FK), product_id (FK, nullable), product_name, barcode,
  quantity (REAL, no CHECK), unit_price, subtotal

settings:
  key (TEXT PK), value (TEXT)

stock_adjustments:
  id, product_id (FK), quantity_change, reason, cashier_id (FK, nullable), created_at

Indexes: 12 indexes on barcode, active, created, ebarimt_status, sale_id,
product_id, category, name, payment_type, return_of_sale_id

Migrations (in migrate_db(), all idempotent):
1. Add admin_password_hash to settings
2. Make cashier_id nullable in sales table
3. Remove quantity CHECK constraint from sale_items
4. Add return_of_sale_id column to sales

В. CSRF хамгаалалт:
────────────────────
- validate_csrf_token() нь request.form БА X-CSRF-Token header-ыг шалгадаг
- CSRF validation хэрэглэсэн: /api/checkout, /api/product/create,
  /api/return/<id>, /api/reprint/<id>, /api/ebarimt-retry
- CSRF exemption: /api/barcode (read-only lookup), /api/customer-state (in-memory only)

Г. Stock validation (create_sale):
──────────────────────────────────
- Сервер талд transaction дотор stock шалгалт
- product exists, is_active, stock_qty >= requested quantity
- SQLite WAL mode тул write нь serialized

Д. Return/Refund (process_return):
─────────────────────────────────
- create_sale()-г payment_type='return' параметрээр дуудаж, атомар гүйлгээгээр
  stock restore, return sale create, original mark-ийг гүйцэтгэдэг
- return_of_sale_id багана: double-return блоклодог
- Return-уудыг eBarimt-ээс хассан (Монголын хуульд буцаалтын баримт шаардлагагүй)

Е. eBarimt (Phase 1 — Бодит API):
───────────────────────────────────
- ebarimt-pos-sdk (EbarimtRestClient) ашиглаж, POS төхөөрөмжийн REST API-тай холбогдоно

- /api/ebarimt-retry endpoint: pending/failed баримтуудыг гараар дахин илгээх
- Startup дээр pending баримтуудыг retry хийдэг (background thread)
- Return sales-ийг eBarimt-ээс хассан, status="skipped"
- Алдаа гарвал status="failed"
- ebarimt_lottery багана sales таблицад (migration-аар нэмэгдэнэ)

8. БҮХ РҮТ / ALL ROUTES (app.py)
================================================================================

POS хуудас (auth шаардлагагүй):
  GET  /                     ← pos.html (product grid + cart)
  GET  /customer             ← customer_display.html
  GET  /api/health           ← {"status": "ok"}
  GET  /api/csrf/refresh     ← CSRF token refresh
  GET  /api/customer-state   ← customer display state (read)
  POST /api/customer-state   ← customer display state (write) - NO CSRF
  POST /api/barcode          ← barcode lookup - NO CSRF (read-only)
  GET  /api/products/search  ← product search
  POST /api/checkout         ← POS checkout (CSRF)
  POST /api/product/create   ← create product from POS (CSRF)
  POST /api/reprint/<id>     ← reprint receipt (CSRF)

Борлуулалтын түүх (auth шаардлагагүй):
  GET  /sales                ← sales.html (pagination + date filter)
  GET  /sales/<id>           ← sale_detail.html

Бараа (admin required):
  GET  /products             ← products.html
  POST /products/create      ← create product form (CSRF)
  POST /products/update/<id> ← update product (CSRF)
  POST /products/delete/<id> ← soft-delete product (CSRF)
  POST /products/restore/<id>← restore product (CSRF)
  POST /products/import      ← CSV import (CSRF)

Тайлан (admin required):
  GET  /reports              ← reports.html
  GET  /reports/export       ← CSV export

Нөөц (admin required):
  GET  /inventory            ← inventory.html
  POST /inventory/adjust     ← stock adjustment (CSRF)

Тохиргоо (admin required):
  GET  /settings             ← settings.html
  POST /settings             ← save settings (CSRF)
  POST /settings/backup      ← manual backup (CSRF)
  POST /settings/change-password ← change admin password (CSRF)

Admin auth (CSRF not needed — uses JSON body + session):
  GET  /api/admin-check-password
  POST /api/admin-set-password
  POST /api/admin-login
  POST /api/admin-logout

Return / eBarimt:
  POST /api/return/<id>      ← process return (CSRF, admin required)
  POST /api/ebarimt-retry    ← retry pending eBarimt (CSRF, admin required)

10. АЮУЛГҮЙ БАЙДАЛ / SECURITY
================================================================================

- CSRF: form body + X-CSRF-Token header
- Admin auth: bcrypt password hashing with SHA-256 fallback
- Session-based admin login with configurable timeout (30-1440 min)
- Session timeout warning at 5 minutes before expiry
- SQL injection: parameterized queries everywhere (no string concatenation)
- XSS: escapeHtml() on user-provided text in cart / customer display
- Input validation: barcode alphanumeric check, price/stock integer validation
- Transaction safety: WAL mode, atomic transactions, rollback on error
- Secret key: from POS_SECRET_KEY env var, hardcoded fallback for development
